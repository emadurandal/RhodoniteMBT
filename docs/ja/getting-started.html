はじめに

RhodoniteMBT は MoonBit と WebGPU で 3D graphics runtime を作るための monorepo です。browser と native SDL3 の両方を対象にし、sample、runtime、ECS、renderer、test harness を同じ workspace で管理します。

最初に覚えるモデル

RhodoniteMBT の実行時は、platform が canvas/window と GPU を用意し、Engine が frame を進め、Scene が表示対象の world を持ち、Renderer が scene の renderable data を WebGPU draw call に変換します。

flowchart LR P[Browser or SDL3 platform] --> E[Engine] E --> S[Scene] S --> W[World / ECS data] W --> R[Renderable entities] E --> G[Renderer] G --> T[Canvas or window surface]

まず動かす

repository root から依存関係を入れ、browser sample を起動します。WebGPU が使える browser で画面が出れば、runtime、sample build、browser platform path が一通り動いています。

pnpm install
pnpm run dev:js:ecs-scene-graph

native path を見る場合は SDL3 を入れたうえで native sample を実行します。

pnpm run dev:native:ecs-scene-graph

読む順番

  1. 用語集で、Engine、Scene、World、Surface などの名前を確認します。
  2. Engine / Sceneで、frame がどの順番で処理されるかを掴みます。
  3. 描画で、mesh/material/renderable が画面に出る流れを確認します。
  4. ECSで、entity と component をどう保持・検索するかを見ます。

この repository の見方

実際に使う facade は moon/rhodonite、低レベルな ECS や math は moon/rhodonite_core、WebGPU wrapper は moon/rhodonite_webgpu、実行例は moon/rhodonite_examples にあります。module の境界や publish 単位は モジュール境界 にまとめています。

Agent 向け

コード変更時は、該当する docs と code を同じ変更で同期します。公開 API、runtime behavior、build/test/publish 手順、sample rendering に触れる場合は、関連する architecture page と README の導線が古くならないか確認します。
