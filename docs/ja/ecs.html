ECS

emadurandal/rhodonite_core/ecs は archetype-based ECS です。任意 component の storage は CPU-only SoA に統一し、renderer upload bytes は builtin packed blob が扱います。

ECS を初めて読む人へ

ECS は、object を class hierarchy ではなく entity ID と component data の組み合わせで表す方法です。RhodoniteMBT の World は entity と component を保持し、system は query で必要な component を持つ entity を探して更新します。内部 storage の SoA や blob は performance と GPU upload のための詳細です。

Storage Model

Maintainer / Agent Notes

ここから先は storage、query、system access、camera-control の詳細です。runtime behavior、history recording、TypeScript wrapper に関わる変更では、このページと mutation coverage / serialization docs を同時に確認します。

flowchart LR W[World] --> R[ComponentRegistry] W --> A[Archetypes] A --> S[sorted component signature] A --> E[dense entity rows] A --> C[CPU SoA component columns] W --> GT[GlobalTransform blob] W --> CB[Camera blob] GT --> GQ[resize/write queues] CB --> CQ[resize/write queues]
  • User-registered component は RegisteredComponent { id, name, cpu_stride, stable_key, schema_version, schema_hash } として登録され、payload は archetype ごとの ComponentColumn に row * stride で packed されます。stable identity metadata は runtime では任意で、将来の history serialization 向けに component_by_stable_key / component_matches_identity で解決できます。
  • GlobalTransform と Camera は CPU row に小さな ref を置き、matrix bytes は専用 blob store に置きます。
  • has_global_transform_blob_write_views と has_camera_blob_write_views は packed blob store に upload slice が queued されているかを返します。renderer は write がない frame の空 drain を避けられますが、write があるときの upload 内容は変わりません。builtin setter は encoded GlobalTransform payload または Camera inputs が変わっていない場合、重複する upload slice を queue しません。Camera の scalar-only update では、より小さい部分 row の GpuWriteView を返すことがあります。
  • CPU column は固定長 buffer を backing storage とし、capacity 拡張時は buffer を差し替えます。JS backend で byte 単位の Array.push hot path を避けます。
  • reserve_batch_capacity と spawn_batch は大量 spawn 時の archetype capacity 拡張を制御する API です。

Query And Mutation

sequenceDiagram participant S as System participant W as World participant Q as Query participant C as CommandBuffer S->>W: declare reads/writes/structural_write S->>Q: prepare or iterate Q->>W: borrow row/column views inside callback S->>C: queue structural changes C->>W: apply after callback/system boundary

QueryRow::read / write は closure の中だけ row bytes を貸し出します。RawQuery::for_each_archetype は hot loop 向けに contiguous column view を返します。query callback 中の直接構造変更や payload setter は guard されるため、構造変更は CommandBuffer に積みます。

Without 相当の filter には Query::new_with_excluded(required, excluded) または RawQuery::new_with_excluded を使います。excluded component は archetype signature filter であり、該当 component を含む archetype を skip しますが、row payload、required_components、component_index は required-only のままです。excluded component id は対象 World に登録済みである必要がありますが、component bytes を読まないため system read 宣言は不要です。

hot loop では Query::component_index / RawQuery::component_index で required component order を事前解決し、read_at、write_at、read_column_at、write_column_at を使えます。index API は component-id API と同じ guard / history behavior を保ちながら、callback 内の component lookup を避けます。row wrapper が不要な read-only row scan では、Query::for_each_read_at、QueryCache::for_each_read_at、PreparedQuery::for_each_read_at、RawQuery::for_each_read_view_at、RawQueryCache::for_each_read_view_at、RawPreparedQuery::for_each_read_view_at が EntityId と indexed row bytes を直接渡します。

Query::plan、RawQuery::plan、PreparedQuery::plan、RawPreparedQuery::plan は callback を実行せずに QueryPlan snapshot を返します。prepared plan は cached archetype version が stale かを示し、stale な診断結果は iteration が使うものと同じ current world の plan として再構築されます。軽量な version check には PreparedQuery::is_stale を使い、繰り返し再利用する prepared plan を更新したい場合は refresh の戻り値を保持し直します。

QueryCache と RawQueryCache は、毎 frame 同じ query を実行する caller 向けにその lifecycle を包みます。これは caller-owned な明示 handle であり、World の global cache ではありません。internal refresh は ECS history 上の mutation ではありません。

Transform Propagation Diagnostics

World::propagate_global_transforms_from_transforms_report は dirty transform propagation path を実行し、GlobalTransform upload view を drain せずに TransformPropagationReport を返します。report には dirty/full path の使用状況、fallback の有無、dirty root 数、skip された dirty entity 数、訪問 entity 数、変更された GlobalTransform row 数、hierarchy index rebuild の有無、pending upload range 数、最初の failure reason、broken ancestor chain / missing GlobalTransform ref / unavailable full archetype path の reason 別 count が含まれます。

この API は debug panel、benchmark、performance investigation 向けです。単に propagation だけが必要な runtime code は、標準 transform propagation system または World::update_global_transforms_from_transforms を使います。

Camera Control

camera control は input source、controller component、transform、lens、Camera blob sync に分かれます。

  • OrbitCameraController、CameraHomeTransform、CameraLens は World::new が builtin camera-control component として登録し、World::orbit_camera_controller_component、World::camera_home_transform_component、World::camera_lens_component で取得する。
  • OrbitCameraController は yaw/pitch、pan、dolly、distance、sensitivity、clamp、reset request を持つ。
  • CameraHomeTransform は reset target の local Transform3D snapshot。
  • CameraLens は projection kind、near/far、aspect、FOV または orthographic half-height。
  • orbit_camera_transform_system は controller から Transform3D と parentless GlobalTransform を更新する。
  • camera_blob_sync_system と orbit_camera_blob_sync_system は GlobalTransform + CameraLens から builtin Camera blob を更新する。

orbit transform system は runtime hot path で raw query plan を cache し、archetype column を直接 iterate します。runtime の direct Camera blob sync system は GlobalTransform blob bytes、CameraLens、OrbitCameraController、Camera ownership の変更で立つ private dirty queue を drain するため、clean frame では camera 全体の scan を避けます。command-buffer Camera blob sync system は editor/history recording compatibility のため full query path を維持します。

runtime update では raw camera-control helper と system を使います。Undo / Redo に参加する editor/authoring 変更では、WorldHistory と一緒に MoonBit の *_tracked helper または TypeScript の *Tracked wrapper を使います。drag gesture のような一連の操作は 1 つの transaction にまとめられます。editor code で system として実行したい場合は orbit_camera_transform_command_system、camera_blob_sync_command_system、orbit_camera_blob_sync_command_system を使い、WorldHistory::run_system_phase 経由で phase を実行します。

TypeScript Wrapper

moon/rhodonite_core/src/ecs/ts は CPU-only ECS surface、ChildOf parent links、query、spawn batch、system scheduling、camera-control bytes、GlobalTransform と Camera blob row helper、builtin blob upload helpers を mirrored API として提供します。npm consumer は rhodonite-mbt/ecs から import します。

query wrapper は QueryPlan、QueryPlanArchetype、QueryCache、RawQueryCache を公開します。Without filter には Query.newWithExcluded、RawQuery.newWithExcluded と cache 版を使い、excludedComponents() で callback payload order に含まれない filter component を確認できます。query.plan(world) または prepared.plan(world) で、callback を実行せずに candidate count、matched row count、matched archetype row count、excluded filter、prepared-plan staleness を確認できます。軽い判定には prepared.isStale(world) を使い、繰り返し iteration する前に prepared.refresh(world) の戻り値を保持します。または cache.forEach(world, ...) に caller-owned cache の refresh を任せます。hot path 向けに componentIndex、*At row / column accessor、cache variant を含む read-only forEachReadAt / forEachReadViewAt callback も公開します。

World.propagateGlobalTransformsFromTransformsReport() は MoonBit の transform propagation diagnostic report を mirror し、failureReason() と failure count getter も公開します。upload view は drain しないため、report を確認した後に renderer upload を進める場合は drainGlobalTransformBlobWriteViews() を呼びます。

wrapper は PhaseKey、SystemContext、System、SystemRunner、callback 内で使う CommandBuffer を公開します。command-buffer system は reads、writes、必要なら structural write permission を宣言して作り、SystemRunner.runPhase(world, ctx, phase) で実行します。World に直接 mutate する commandless system には System.newDirect を使います。direct system も access guard と batching は維持しますが、直接 write は WorldHistory.runSystemPhase では記録されません。SystemRunner.planPhase(phase) は phase execution と同じ cached greedy batching rule を使い、実行せずに SystemPhasePlan / SystemPlanBatch / SystemPlanSystem snapshot を返します。SystemRunner.parallelAccessConflicts() は同じ phase で並列実行できない pair の read-only diagnostics を返し、hasParallelAccessConflicts() はその boolean 版です。SystemRunner.runPhaseReport は同じ phase を実行し、direct system と empty command buffer の system も含めて batch / system / failed command ごとの診断を含む SystemRunReport を返します。command-buffer mutation を undo/redo に記録する場合は WorldHistory.runSystemPhase(..., label) または runSystemPhaseReport を使います。

npm root entrypoint では app scheduler の string PhaseKey を PhaseKey として維持し、ECS wrapper class は EcsPhaseKey でも export します。rhodonite-mbt/ecs subpath では ECS class を PhaseKey として export します。

Undo / Redo

Undo/Redo は World の上に置く optional な tracked transaction layer、WorldHistory が提供します。対象範囲、EntityId 復元、enabled state、performance notes は Undo / Redo に分けています。
