Rendering Architecture

描画の詳細は facade runtime の emadurandal/rhodonite/app にあります。現在の renderer は unlit static mesh と sample-driven instancing のための narrow な v1 path です。

Renderer v1

Renderer は Engine が所有し、device-wide GPU resources を所有します。visible Renderable + GlobalTransform entity を query し、scene main camera の builtin Camera blob と GlobalTransform blob を upload して、caller-supplied RenderTargetResources へ unlit static indexed mesh を描画します。

flowchart TB E[Engine] --> R[Renderer] E --> RT[RenderTargetResources] S[Scene] --> W[World] W --> Q[Renderable + GlobalTransform query] R --> M[Mesh table] R --> Mat[Material table] R --> I[Instance buffer table] Q --> Draw[Draw commands] M --> Draw Mat --> Draw I --> Draw RT --> Draw

Texture、skinning、transparent sorting、shadow、LOD はまだ v1 renderer の責務ではありません。

Renderable Model

  • RenderableDesc は entity と登録済み mesh/material handle を結びます。
  • RenderableFlags は render visibility などの per-renderable state を持ちます。
  • Renderable component id は Scene が内部で登録・所有します。
  • scene render pass は Renderable data と GlobalTransform の両方を持つ entity を抽出します。

Resource Registration

Renderable は mesh/material handle 値を ECS に保存しますが、その handle は Renderer-owned table を指します。Undo/Redo は Renderable component bytes を復元できますが、mesh、material、instance buffer、その他 GPU resource は再作成しません。renderable の履歴を保持する application は、resource handle が history record より長く生きることを保証するか、Renderer の上位に asset/resource history を追加する必要があります。

editor operation では WorldHistory と一緒に add_renderable_tracked、set_renderable_tracked、remove_renderable_tracked を使います。raw な add_renderable と set_renderable は direct ECS mutation のままです。

APIPurpose
register_static_indexed_mesh_desccaller が記述した indexed mesh を upload し、MeshHandle を返します。
register_cube_meshCubeMeshDesc / cube_mesh_desc から built-in position-only cube primitive を登録します。
register_unlit_materialv1 mesh path で使う unlit material を登録します。
register_static_instance_buffer明示的な instanced draw path 用の per-instance transform/color data を登録します。

Draw Paths

  • render_scene_renderables(scene, target, view) は通常の scene path です。ECS state から renderable を抽出し、登録済み mesh/material handle 経由で描画します。
  • render_instanced_mesh(scene, mesh, instances, count, target, view) は MassCubes が使う明示的な instanced path です。大量 cube sample を、cube ごとの renderable draw ではなく packed instance-buffer path に乗せます。

Example Mapping

  • ecs-scene-graph は小さな hierarchy を通常の scene renderable path で描画します。
  • ecs-custom-component-color は独自 ECS component を定義し、それを renderer instance color に同期します。
  • ecs-mass-cubes は shared scene/camera state と明示的な instanced path を使って多数の cube を描画します。
  • basic-triangle と ondemand-triangle は lower-level WebGPU sample です。engine phase と platform setup は使いますが、Renderer v1 ではなく sample 側で pipeline を直接所有します。
