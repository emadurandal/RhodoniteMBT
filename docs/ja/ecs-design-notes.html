ECS Design Notes

このページは現行 ECS の設計上の注意点をまとめます。汎用 GPU component storage は削除済みで、現在は CPU-only archetype SoA と builtin packed GPU blob に統一されています。

Query View Lifetime

QueryRow::read / write と RawQueryRow::read_view / write_view は closure-scoped view を返します。view を外へ逃がさない API 形状にしているため、system 実行順や将来の並列化に向けた最低限の境界を保ちます。

index-based query accessor は required component order を payload index として使います。これは hot-loop helper であり、別種の lifetime handle ではありません。component-id accessor と同じ access guard を維持します。

query の excluded component は archetype signature filter 専用です。QueryPlan diagnostics には copy されますが、payload slot ではなく、component_index では解決できず、row / column view の lifetime も延ばしません。

RawQueryArchetype::write_column は archetype column 全体の mutable view を貸し出す untracked expert API です。同一 component の重複 mutable view を避けるため、query required set の duplicate check に依存します。full-column write を undo/redo tracking したい場合は RawQueryArchetype::write_column_tracked を使います。呼び出し側が変更候補の sparse column rows を知っている場合は RawQueryArchetype::write_column_rows_tracked を使います。

QueryPlan は diagnostic snapshot であり、borrow や ownership handle ではありません。required component ids と matched archetype row counts を copy するため、row/column view の lifetime を延ばさずに query shape を確認できます。

PreparedQuery と RawPreparedQuery は immutable lifecycle handle です。is_stale は version check のみで、refresh は繰り返し再利用する前に呼び出し側が保持し直す current prepared plan value を返します。prepared plan は matched archetype ごとの row / column access metadata を保持するため、row iteration のたびに component lookup map を作り直しません。

QueryCache と RawQueryCache は caller-owned mutable handle です。初回または stale 時に内部 prepared plan を更新し、通常の iteration では同じ plan を再利用します。World に global cache を持たせず、system や editor helper が cache lifetime を明示的に所有します。

SystemRunner Access Declaration

  • 現行実装は single-thread 実行ですが、System は reads / writes / structural_write を宣言します。
  • writes は同じ component の read も許可します。
  • entity/archetype 構造を変える API は structural_write を要求します。
  • CommandBuffer は queue 時点で component write と structural write を検証します。
  • component 登録は system runner 実行中に lock されます。
  • SystemRunner は phase batches を内部 cache し、system 追加時に invalidation します。公開 plan result は snapshot のままです。
  • SystemRunner::run_phase_report は run_phase と同じ command-buffer path を実行します。report は execution snapshot であり、batch order、command apply order、history behavior は変えません。
  • builtin TransformPropagation system は内部 dirty queue と lazy な ChildOf hierarchy index を使います。dirty root は indexed subtree を parent-first に再計算し、公開 World::update_global_transforms_from_transforms は互換性のため full recompute API のままです。

Builtin Packed Blobs

flowchart LR Row[CPU ref component row] --> Off[format and word offset] Off --> Blob[Packed GPU blob bytes] Blob --> Resize[resize events] Blob --> Writes[GpuWriteView write drains] Writes --> Renderer[Renderer upload]

GlobalTransform と Camera は CPU ref component と packed GPU blob の二層構造です。GpuWriteView は blob backing storage の借用 view なので、同じ blob を次に mutate / resize する前に upload まで終える必要があります。dirty write view は drain 前に昇順へ並べ、重複または隣接 range だけを正規化するため、未変更の gap を跨いで upload せずに renderer 側の余計な queue write を避けます。

Removed Responsibilities

以下の責務は現在の ECS には残していません。

  • arbitrary component の GPU upload queue
  • entity index 固定の component payload storage
  • component kind 分岐
  • component ごとの active index set

GPU 向けデータを追加する場合は、まず builtin blob と同じ dedicated store にするか、CPU SoA から renderer extraction で明示的に pack します。

Test Focus

  • archetype move 時の CPU column copy
  • query / raw query の row and column view
  • system runner access guard と CommandBuffer
  • GlobalTransform / Camera blob allocation、resize event、write drain
  • TypeScript wrapper の ByteView と builtin blob upload helper
