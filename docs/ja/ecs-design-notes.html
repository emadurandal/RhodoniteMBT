ECS Design Notes

このページは現行 ECS の設計上の注意点をまとめます。汎用 GPU component storage は削除済みで、現在は CPU-only archetype SoA と builtin packed GPU blob に統一されています。

Query View Lifetime

QueryRow::read / write と RawQueryRow::read_view / write_view は closure-scoped view を返します。view を外へ逃がさない API 形状にしているため、system 実行順や将来の並列化に向けた最低限の境界を保ちます。

RawQueryArchetype::write_column は archetype column 全体の mutable view を貸し出す expert API です。同一 component の重複 mutable view を避けるため、query required set の duplicate check に依存します。

SystemRunner Access Declaration

  • 現行実装は single-thread 実行ですが、System は reads / writes / structural_write を宣言します。
  • writes は同じ component の read も許可します。
  • entity/archetype 構造を変える API は structural_write を要求します。
  • CommandBuffer は queue 時点で component write と structural write を検証します。
  • component 登録は system runner 実行中に lock されます。

Builtin Packed Blobs

flowchart LR Row[CPU ref component row] --> Off[format and word offset] Off --> Blob[Packed GPU blob bytes] Blob --> Resize[resize events] Blob --> Writes[GpuWriteView write drains] Writes --> Renderer[Renderer upload]

GlobalTransform と Camera は CPU ref component と packed GPU blob の二層構造です。GpuWriteView は blob backing storage の借用 view なので、同じ blob を次に mutate / resize する前に upload まで終える必要があります。

Removed Responsibilities

以下の責務は現在の ECS には残していません。

  • arbitrary component の GPU upload queue
  • entity index 固定の component payload storage
  • component kind 分岐
  • component ごとの active index set

GPU 向けデータを追加する場合は、まず builtin blob と同じ dedicated store にするか、CPU SoA から renderer extraction で明示的に pack します。

Test Focus

  • archetype move 時の CPU column copy
  • query / raw query の row and column view
  • system runner access guard と CommandBuffer
  • GlobalTransform / Camera blob allocation、resize event、write drain
  • TypeScript wrapper の ByteView と builtin blob upload helper
