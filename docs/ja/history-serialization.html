履歴シリアライズ

この文書は WorldHistory export/import に向けた永続化境界を定義します。現行実装は draft の in-memory archive shape を公開していますが、永続 file encoding は未実装です。

Status

  • WorldHistory::export_undo_stack(world) と WorldHistory::export_redo_stack(world) は、保持中の全 record が serialization 可能な場合に draft in-memory archive を返します。
  • WorldHistory::import_undo_stack(world, archive) と WorldHistory::import_redo_stack(world, archive) は archive を検証し、target stack を置き換えます。world は変更しません。
  • WorldHistory::validate_import_undo_stack(world, archive) と WorldHistory::validate_import_redo_stack(world, archive) は、record / delta 位置を含む dry-run import validation report を返します。
  • TypeScript wrapper は exportUndoStack、exportRedoStack、importUndoStack、importRedoStack、validateImportUndoStack、validateImportRedoStack を公開します。export 時の payload bytes は Uint8Array に copy され、import 時は plain object archive も復元できます。
  • TypeScript npm surface は JSON archive string format 用に encodeHistoryExportJson と decodeHistoryExportJson も公開します。
  • Import/export と JSON archive encoding は format_version = 1 を使います。MoonBit core は in-memory object model のみを公開し、JSON encoding は TypeScript 側で実装します。
  • undo_summary と redo_summary は retained in-memory record の diagnostic view です。serialized history archive や compatibility format ではありません。
  • MoonBit の enum layout、object layout、内部 variant 名は stable file ABI として扱いません。
  • serialized form は editor/session persistence 向けです。任意の runtime simulation や GPU resource state の replay は対象にしません。

Record Shape

将来の history archive は undo stack と redo stack を ordered record として保存します。各 record は label、record-level metadata、ordered delta を持ちます。create 後に component を追加する transaction のように、delta の順序そのものが意味を持ちます。

FieldPolicy
format_version必須です。未対応の major version は推測せず reject します。
library_version診断 metadata です。互換性判断は format_version と schema key で行います。
recordscommitted undo/redo record を stack order で保存します。
label任意の UI metadata です。replay semantics には影響しません。
deltas明示的な variant tag と typed payload field を持つ ordered logical delta です。

Identity

Entity identity は runtime restoration policy と同じく index + generation として保存します。destroy の Undo は同じ EntityId を復元します。Component identity にはより強い規則が必要です。ComponentTypeId.index は session-local なので、永続化された key として単独では使いません。

IdentitySerialization policy
Entityindex と generation を保存します。import は target world がその id を reserve / restore できることを検証します。
Builtin componentTransform3D、ChildOf、GlobalTransform、Camera のような stable builtin name を保存します。
User CPU componentregister_cpu_component_with_identity で登録し、application-provided stable key と schema version または hash を持つことを必須にします。登録済み component と一致しない場合は replay を reject します。
Component indexlocal hint として cache してもよいですが、session をまたいだ authoritative key にはしません。

Payloads

User CPU component は byte-exact payload として扱います。before/after bytes は対応する component schema key と一緒に保存された場合だけ安全に replay できます。import validation は component_by_stable_key で登録済み component を解決し、component_matches_identity で照合します。指定された schema version/hash field は一致必須で、未指定の schema field は wildcard として扱います。schema が変わった場合、bytes を再解釈せず delta を reject します。

Blob-backed builtin では CPU ref bytes を source of truth として永続化しません。GlobalTransform は logical matrix row と format metadata を保存します。Camera は logical camera GPU row payload と runtime helper に必要な camera metadata を保存します。import 時は現在の session の world が新しい blob row を割り当て、その payload を書き込み、有効な CPU ref component を作ります。

Export MVP

現行 export API は、次に Undo / Redo される operation が先頭になる stack order で retained record を返します。先に undo_serialization_report / redo_serialization_report と同じ eligibility check を実行し、1 件でも serialization 不可の record があれば None / null を返します。この処理は history diagnostic や stack を変更しません。

DeltaExported payload
entity_createdEntity id のみ。
entity_destroyedEntity id、stable component identity、copy 済み component bytes。
component_addedStable component identity と after bytes。
component_removedStable component identity と before bytes。
component_changedStable component identity、before bytes、after bytes。
global_transform_changedStable builtin identity、logical row bytes、global_transform_format code。
camera_changedStable builtin identity と logical camera row bytes。GlobalTransform format field はありません。

Import MVP

Import は同じ in-memory archive shape を読み込み、target stack だけを置き換えます。既存 record への append はせず、反対側 stack も clear しません。target world は archive が表す現在状態とすでに一致している必要があります。stack を置き換える前に、全 record をその world に対して検証します。

validation report API は同じ archive conversion と full-stack applicability check を実行しますが、history stack、world、last_diagnostic を変更しません。top-level / record-level / delta-level の各 report は valid、reason、archive order の index を返します。record index 0 は次に import される Undo / Redo operation です。delta index は、Undo validation が内部で逆順適用を検証する場合でも、元の archive order を指します。

FailureDiagnostic
未対応の format_versionimport_unsupported_format
record / delta shape が不正import_invalid_archive
stable component identity が解決できない、または一致しないimport_identity_mismatch
payload format、byte length、row format が不正import_invalid_payload
import stack 全体を current world に適用できないimport_validation_failed

JSON Archive MVP

encodeHistoryExportJson は TypeScript の HistoryExport を JSON string に変換します。decodeHistoryExportJson はその JSON string を検証し、importUndoStack / importRedoStack に渡せる HistoryExport を返します。

FieldJSON policy
NamingArchive field は format_version、record_count、delta_count、local_component、global_transform_format のような snake_case を使います。
Entity{ index, generation } として保存します。
ComponentStable component identity metadata と併せて、local hint として { index } を保存します。
Bytesbytes_base64 として保存します。MVP decoder は number-array byte payload を出力せず、受け付けません。
Validation未対応 version、不正な JSON shape、未対応 delta kind、不正 base64、record/delta count 不一致は Error を throw します。

Replay Validation

import と replay は runtime undo/redo と同じ防御方針を使います。record 適用前に検証し、stale delta や schema mismatch を reject し、検証失敗時は stack を動かしません。byte budget と record count limit は runtime retention policy であり、archive compatibility policy ではありません。

undo_serialization_report と redo_serialization_report は retained in-memory stack 向けの dry-run diagnostic です。payload bytes は export せず、file format も定義しません。各 report は全 record / delta を含み、serialization 可能かどうかと、missing_stable_component_identity や unknown_component などの失敗理由を返します。editor は export 実装前でも stable identity metadata が必要な component を表示できます。

Out Of Scope For V1

  • Renderer の mesh/material object、GPU buffer、device resource。
  • ECS component bytes から参照される asset lifetime と external resource handle。
  • collaborative editing merge、conflict resolution、operation transform。
  • 明示的な format_version compatibility policy を超えた cross-engine-version replay。
  • open transaction の serialization。永続化対象候補は committed undo/redo record のみです。
