Engine / Scene Architecture

現在の runtime は emadurandal/rhodonite/app の public facade にあります。古い prototype / phase 計画は完了済みで、examples は facade runtime を直接使います。

Runtime Ownership

flowchart TB E[Engine] --> GC[GPUContext] E --> T[TimeState] E --> PH[Phase handlers and groups] E --> SF[Surface list] E --> S[Scene list] SF --> SI[surface-local InputState] SF --> SS[SurfaceState] SF --> RT[RenderTargetResources] S --> W[World] S --> SR[SystemRunner] E --> R[Renderer] R[Renderer] --> GPU[device-wide GPU resources] RT --> TG[surface-sized target resources] R --> S W --> ECS[ECS data and builtin blobs]
TypeResponsibility
EngineGPUContext、標準 Renderer、render target resources、scenes、surfaces、time、input、phase groups、on-demand render state を所有する。
Scene1つの World と SystemRunner、main camera、enabled/visible state を持つ runtime scene。
WorldECS storage。engine lifecycle や GPU resource ownership は持たない。
Rendererdevice-wide GPU resources、explicit pipeline layouts、format-keyed pipeline、mesh/material/instance buffer table、scene renderable extraction と draw を扱う。
RenderTargetResourcescolor format、extent、depth attachment など surface-local render target state を所有する。
FrameStatedelta、frame index、elapsed、surface snapshot、surface-local input を phase/system へ渡す。

Phase Groups

flowchart TD A["rhodonite/frame_begin"] --> A1["rhodonite/surface"] A1 --> A2["rhodonite/input"] A2 --> B["rhodonite/fixed_step 0..max_fixed_steps_per_frame"] B --> B1["rhodonite/fixed_update"] B1 --> B2["rhodonite/fixed_post_update"] B2 --> C["rhodonite/render_frame"] C --> C1["rhodonite/update"] C1 --> C2["rhodonite/post_update"] C2 --> C3["rhodonite/render_extract"] C3 --> C4["rhodonite/render_prepare"] C4 --> C5["rhodonite/render"] C5 --> C6["rhodonite/present"]

Engine::run_frame(delta_seconds) は frame-begin、fixed-step、render-frame group を標準順序で実行します。各 phase は PhaseSlot::BeforeSystems handlers、enabled/visible scene systems、AfterSystems handlers の順に処理されます。

  • phase_startup() と phase_shutdown() は one-shot phase。group には追加しません。
  • custom phase group / phase order の編集は Engine::initialize() 中の startup handler で行います。
  • Engine::add_phase_handler は registration key を受け取れます。同じ phase、slot、key の handler は重複登録されません。
  • 通常の scene-scoped callback には Engine::on_scene_update / Engine::on_scene_render（TypeScript では Engine.onSceneUpdate / Engine.onSceneRender）を使います。標準 update/render phase と slot、multi-surface frame の対象 scene 判定、scene の enabled/visible 判定を隠蔽します。frame-wide な callback には Engine::on_frame_update / Engine::on_frame_render（TypeScript では Engine.onFrameUpdate / Engine.onFrameRender）を使い、custom phase や slot が必要な場合だけ Engine::add_phase_handler を使います。
  • Scene は main camera が設定された時点で標準 transform/camera runtime integration を暗黙宣言します。scene は builtin orbit/home/lens component id を使います。MoonBit sample は transform propagation や orbit camera blob sync などの optional standard system の bool flag を変えたいときだけ Scene::use_common_runtime を呼びます。TypeScript sample は対応する Scene.useCommonRuntime を使います。Engine::initialize() と scene 単体の prepare_render_state がこの宣言を common scene systems に反映し、engine 管理下の scene には orbit-camera input handler も追加します。TypeScript の default transform propagation は scene world が world.updateGlobalTransformsFromTransforms() を公開していればそれを呼びます。custom world は propagateTransforms を渡せ、sample 側は transformPropagation: false で無効化できます。Engine::set_surface_scene / Engine.setSurfaceScene で scene を surface に bind したときも、宣言済み orbit-camera input handler がその scene 向けに追加されます。
  • Scene 単体や offscreen rendering では、Scene::prepare_render_state で update、post_update、render_extract を一度に実行でき、各 phase をユーザーコードに並べる必要はありません。
  • surface suspended 中は update までは進み、render extraction 以降は skip されます。
  • on-demand mode では dirty でない間 frame 自体を走らせません。見た目が変わる state mutation 後は利用側が request_render を呼びます。

Surface Model

single-surface では Engine::set_surface_active / set_surface_suspended が surface snapshot と render target resources を更新します。multi-surface では Engine::add_surface、add_surface_for_scene、set_surface_scene、surface_input、run_multi_surface_frame を使います。

flowchart LR P[Platform event loop] --> E[Engine] E --> S1[Surface A: canvas/window/input] E --> S2[Surface B: canvas/window/input] S1 --> Scene1[Scene A systems and render] S2 --> Scene2[Scene B systems and render]

各 surface は surface-local InputState と RenderTargetResources を持ちます。canvas/window A の pointer event は B の camera/controller に影響しません。

Rendering

Engine は標準 Renderer を所有し、scene は renderer path が消費する ECS data を提供します。Renderer、Renderable、resource registration、draw path の詳細は Rendering Architecture に分けています。

Sample Layout

samples は DemoState という名前で sample-local GPU/pipeline/state をまとめ、platform setup から demo state を作成して register_engine_handlers(engine, demo_state) で engine に接続する方向に揃えています。ECS samples は Scene を render source とし、basic triangle のような low-level sample は main scene を実行境界としてだけ使います。
