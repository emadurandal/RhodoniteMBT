Rendering Architecture

Rendering details live under the facade runtime in emadurandal/rhodonite/app. The current renderer is a narrow v1 path for unlit static meshes and sample-driven instancing.

Renderer v1

Renderer is owned by Engine and owns device-wide GPU resources. It queries visible Renderable + GlobalTransform entities, uploads the scene main camera's builtin Camera blob and GlobalTransform blob, and draws unlit static indexed meshes into caller-supplied RenderTargetResources.

flowchart TB E[Engine] --> R[Renderer] E --> RT[RenderTargetResources] S[Scene] --> W[World] W --> Q[Renderable + GlobalTransform query] R --> M[Mesh table] R --> Mat[Material table] R --> I[Instance buffer table] Q --> Draw[Draw commands] M --> Draw Mat --> Draw I --> Draw RT --> Draw

Textures, skinning, transparent sorting, shadows, and LOD are not v1 renderer responsibilities yet.

Renderable Model

  • RenderableDesc links an entity to registered mesh and material handles.
  • RenderableFlags carries render visibility and related per-renderable state.
  • The Renderable component id is registered and owned internally by Scene.
  • A scene render pass extracts entities that have both Renderable data and a GlobalTransform.

Resource Registration

APIPurpose
register_static_indexed_mesh_descUploads a caller-described indexed mesh and returns a MeshHandle.
register_cube_meshRegisters the built-in position-only cube primitive from CubeMeshDesc / cube_mesh_desc.
register_unlit_materialRegisters an unlit material used by the v1 mesh paths.
register_static_instance_bufferRegisters per-instance transform/color data for explicit instanced draw paths.

Draw Paths

  • render_scene_renderables(scene, target, view) is the normal scene path. It extracts renderables from ECS state and draws them through registered mesh/material handles.
  • render_instanced_mesh(scene, mesh, instances, count, target, view) is the explicit instanced path used by MassCubes. It keeps the high-count sample on a packed instance-buffer path instead of creating one renderable draw per cube.

Example Mapping

  • ecs-scene-graph uses the normal scene renderable path for a small hierarchy.
  • ecs-mass-cubes uses shared scene/camera state and the explicit instanced path for many cubes.
  • basic-triangle and ondemand-triangle are lower-level WebGPU samples. They use engine phases and platform setup, but own their pipeline directly instead of using Renderer v1.
