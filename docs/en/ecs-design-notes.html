ECS Design Notes

The current ECS is CPU-only archetype SoA plus builtin packed GPU blobs. Generic GPU component storage has been removed.

Query View Lifetime

QueryRow::read / write and RawQueryRow::read_view / write_view return closure-scoped views. Read-only indexed fast paths such as PreparedQuery::for_each_read_at keep the same callback-scoped row view lifetime while avoiding per-row wrapper construction.

Index-based query accessors use the required component order as the payload index. They are hot-loop helpers, not separate lifetime handles, and keep the same access guards as the component-id accessors.

Excluded query components are archetype-signature filters only. They are copied into QueryPlan diagnostics, but they are not payload slots, cannot be resolved with component_index, and do not extend row or column view lifetimes.

RawQueryArchetype::write_column is an expert untracked API that lends a mutable view of a whole archetype column. It relies on duplicate required-component rejection to avoid overlapping mutable views for the same component. Use RawQueryArchetype::write_column_tracked when a full-column write needs undo/redo tracking. Use RawQueryArchetype::write_column_rows_tracked when the caller already knows the sparse column rows that may change.

QueryPlan is a diagnostic snapshot, not a borrow or ownership handle. It copies required component ids and matched archetype row counts so callers can inspect query shape without extending row/column view lifetimes.

PreparedQuery and RawPreparedQuery are immutable lifecycle handles. is_stale is only a version check; refresh returns the current prepared plan value that callers should retain before repeated reuse. Prepared plans hold row and column access metadata per matched archetype so row iteration does not rebuild component lookup maps during each run.

QueryCache and RawQueryCache are caller-owned mutable handles. They deliberately avoid a global World cache so lifetime, memory use, and cross-world ownership stay explicit.

The hot orbit camera transform systems own RawQueryCache values and iterate matched archetypes directly. They still use the public World setter for GlobalTransform writes, while Transform3D component writes go through RawQueryArchetype::write_column_at so dirty transform propagation sees the changed archetype.

SystemRunner Access Declarations

  • Execution is currently single-threaded, but systems declare reads, writes, and structural_write.
  • writes also permits reads of the same component.
  • Entity/archetype structural mutation requires structural_write.
  • CommandBuffer validates component writes and structural writes at queue time.
  • Component registration is locked while the system runner is executing.
  • SystemRunner caches phase batches internally and invalidates them when systems are added; public plan results remain snapshots.
  • System::new_direct builds commandless systems for hot paths that mutate through World directly. Direct systems still use declared access guards and batching, but they do not allocate a CommandBuffer and their direct writes are not recorded by WorldHistory::run_system_phase.
  • The builtin runtime camera blob sync systems are direct systems; use the *_command_system variants when those writes must be recorded through WorldHistory.
  • Non-report phase execution skips the command-buffer apply pass for command systems that queued no commands.
  • SystemRunner::run_phase_report still emits per-system diagnostics for direct systems and empty command buffers; the report is an execution snapshot and does not change batch ordering, command apply order, or history behavior.
  • The builtin TransformPropagation system uses an internal dirty queue plus a lazy ChildOf hierarchy index. Dirty roots are recomputed parent-first through their indexed subtree, while the public World::update_global_transforms_from_transforms API remains a full recompute path for compatibility.
  • World::propagate_global_transforms_from_transforms_report runs the diagnostic dirty propagation path and returns counters for dirty roots, skipped entries, visited entities, changed GlobalTransform rows, hierarchy-index rebuilds, pending upload ranges, and categorized failure reasons without draining the blob.

Builtin Packed Blobs

flowchart LR Row[CPU ref component row] --> Off[format and word offset] Off --> Blob[Packed GPU blob bytes] Blob --> Resize[resize events] Blob --> Writes[GpuWriteView write drains] Writes --> Renderer[Renderer upload]

GlobalTransform and Camera use two layers: a CPU ref component row plus packed GPU blob bytes. GpuWriteView borrows blob backing storage, so upload it before mutating or resizing the same blob again. Dirty write views are normalized into ascending, overlapping-or-adjacent ranges before drain so renderer upload avoids unnecessary queue writes without uploading across untouched gaps.

Removed Responsibilities

  • Generic component GPU upload queues.
  • Entity-index-fixed component payload storage.
  • Component kind branching.
  • Per-component active index sets.

New GPU-facing data should use a dedicated store like builtin blobs, or be explicitly packed during renderer extraction from CPU SoA data.

Test Focus

  • CPU column copying during archetype moves.
  • Query/raw query row and column views.
  • SystemRunner access guards and CommandBuffer.
  • GlobalTransform / Camera allocation, resize events, and write drains.
  • TypeScript wrapper ByteView and builtin blob upload helpers.
