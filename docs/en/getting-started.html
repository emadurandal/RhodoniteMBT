Getting Started

RhodoniteMBT is a MoonBit and WebGPU monorepo for building a 3D graphics runtime. It targets both browsers and native SDL3, and keeps samples, runtime code, ECS, rendering, and test harnesses in one workspace.

The First Mental Model

At runtime, a platform creates the canvas/window and GPU context, Engine advances frames, Scene owns the world being displayed, and Renderer turns renderable scene data into WebGPU draw calls.

flowchart LR P[Browser or SDL3 platform] --> E[Engine] E --> S[Scene] S --> W[World / ECS data] W --> R[Renderable entities] E --> G[Renderer] G --> T[Canvas or window surface]

Run Something First

From the repository root, install dependencies and start a browser sample. If it renders in a WebGPU-capable browser, the runtime, sample build, and browser platform path are working together.

pnpm install
pnpm run dev:js:ecs-scene-graph

For the native path, install SDL3 first and then run the matching native sample.

pnpm run dev:native:ecs-scene-graph

Suggested Reading Order

  1. Use the Glossary to map names such as Engine, Scene, World, and Surface.
  2. Read Engine / Scene to understand frame ownership and phase order.
  3. Read Rendering to see how meshes, materials, and renderables reach the screen.
  4. Read ECS to understand how entities and components are stored and queried.

How To Read This Repository

The facade most users touch lives in moon/rhodonite, low-level ECS and math live in moon/rhodonite_core, WebGPU wrappers live in moon/rhodonite_webgpu, and runnable examples live in moon/rhodonite_examples. Module boundaries and release units are described in Module Boundaries.

For Agents

When code changes, keep the matching docs in the same change. For public APIs, runtime behavior, build/test/publish steps, or sample rendering changes, check whether the related architecture page and README entry points still describe the current system.
