ECS

emadurandal/rhodonite_core/ecs is an archetype-based ECS. Arbitrary component storage is CPU-only SoA; renderer upload bytes are handled by builtin packed blob stores.

Storage Model

flowchart LR W[World] --> R[ComponentRegistry] W --> A[Archetypes] A --> S[sorted component signature] A --> E[dense entity rows] A --> C[CPU SoA component columns] W --> GT[GlobalTransform blob] W --> CB[Camera blob] GT --> GQ[resize/write queues] CB --> CQ[resize/write queues]
  • User components are registered as RegisteredComponent { id, name, cpu_stride, stable_key, schema_version, schema_hash } and packed into per-archetype ComponentColumn buffers. Stable identity metadata is optional at runtime and can be resolved with component_by_stable_key / component_matches_identity for future history serialization.
  • GlobalTransform and Camera store small CPU refs in rows; their matrix bytes live in dedicated blob stores.
  • has_global_transform_blob_write_views and has_camera_blob_write_views report whether those packed blob stores currently have queued upload slices, so renderers can skip empty drains without changing what gets uploaded when writes exist. Builtin setters skip queuing duplicate slices when the encoded GlobalTransform payload or Camera inputs are unchanged; Camera scalar-only updates may return a smaller partial-row GpuWriteView.
  • CPU columns grow by replacing fixed backing buffers instead of appending bytes one at a time, which avoids large JS Array.push hot paths.
  • reserve_batch_capacity and spawn_batch control archetype capacity for large spawn batches.

Queries And Mutation

QueryRow::read and write lend row bytes only inside the closure. RawQuery::for_each_archetype returns contiguous column views for hot loops. Direct structural mutation and payload setters are guarded while query callbacks are active; queue structural changes through CommandBuffer.

Use Query::new_with_excluded(required, excluded) or RawQuery::new_with_excluded for Without-style filters. Excluded components are archetype-signature filters: matching skips archetypes that contain them, but row payloads, required_components, and component_index remain required-only. Excluded component ids must be registered in the target World, but they do not require a system read declaration because their bytes are never read.

Hot loops can pre-resolve required component order with Query::component_index / RawQuery::component_index and then use read_at, write_at, read_column_at, or write_column_at. The index APIs keep the same guard and history behavior as the component-id APIs while avoiding repeated component lookup inside callbacks. For read-only row scans that do not need a row wrapper, Query::for_each_read_at, QueryCache::for_each_read_at, PreparedQuery::for_each_read_at, RawQuery::for_each_read_view_at, RawQueryCache::for_each_read_view_at, and RawPreparedQuery::for_each_read_view_at pass EntityId plus the indexed row bytes directly.

Query::plan, RawQuery::plan, PreparedQuery::plan, and RawPreparedQuery::plan return QueryPlan snapshots without running callbacks. Prepared plans report whether their cached archetype version is stale; stale diagnostics are rebuilt against the current world, matching the plan that iteration would use. Use PreparedQuery::is_stale for a lightweight version check and refresh when the caller wants to keep a rebuilt prepared plan for repeated reuse.

QueryCache and RawQueryCache wrap that lifecycle for callers that run the same query every frame. They are explicit handles owned by the caller, not global World caches; their internal refresh is read-only with respect to ECS history.

Transform Propagation Diagnostics

World::propagate_global_transforms_from_transforms_report runs the dirty transform propagation path and returns a TransformPropagationReport without draining GlobalTransform upload views. The report exposes whether the dirty or full path ran, whether a fallback happened, dirty root and skipped entity counts, visited entity and changed GlobalTransform row counts, hierarchy-index rebuild state, pending upload range count, and the first failure reason plus reason-specific counts for broken ancestor chains, missing GlobalTransform refs, and unavailable full archetype paths.

Use this API for debug panels, benchmarks, and performance investigation. Runtime code that only needs propagation should keep using the standard transform propagation system or World::update_global_transforms_from_transforms.

Camera Control

Camera control is split into input source, controller component, transform, lens, and Camera blob sync. World::new registers OrbitCameraController, CameraHomeTransform, and CameraLens as builtin camera-control components; callers retrieve their ids with World::orbit_camera_controller_component, World::camera_home_transform_component, and World::camera_lens_component. The transform systems update Transform3D / GlobalTransform; blob sync systems write the builtin Camera blob from GlobalTransform + CameraLens.

The orbit transform systems cache their raw query plan and iterate archetype columns directly on hot runtime paths. Runtime direct Camera blob sync systems drain a private dirty queue populated by GlobalTransform, CameraLens, OrbitCameraController, and Camera ownership changes, so clean frames skip full camera scans. Command-buffer Camera blob sync systems keep the full query path for editor/history recording compatibility.

Use raw camera-control helpers and systems for runtime updates. For editor/authoring changes that must participate in Undo / Redo, use the *_tracked MoonBit helpers or the TypeScript *Tracked wrappers with WorldHistory; gesture-sized operations can be grouped in one transaction. When editor code wants a system-shaped path, use orbit_camera_transform_command_system, camera_blob_sync_command_system, or orbit_camera_blob_sync_command_system and run the phase through WorldHistory::run_system_phase.

TypeScript Wrapper

moon/rhodonite_core/src/ecs/ts mirrors the CPU-only ECS surface, ChildOf parent links, query APIs, spawn batch, system scheduling, camera-control byte layouts, GlobalTransform and Camera blob row helpers, and builtin blob upload helpers. npm users import it from rhodonite-mbt/ecs.

The query wrappers expose QueryPlan, QueryPlanArchetype, QueryCache, and RawQueryCache. Use Query.newWithExcluded, RawQuery.newWithExcluded, and the cache equivalents for Without filters; excludedComponents() reports those filters without adding them to callback payload order. Use query.plan(world) or prepared.plan(world) to inspect candidate counts, matched row counts, matched archetype row counts, excluded filters, and prepared-plan staleness without executing query callbacks. Use prepared.isStale(world) for a cheap check, then keep the result of prepared.refresh(world) before repeated iteration, or let cache.forEach(world, ...) refresh its caller-owned cache as needed. Hot wrappers also expose componentIndex, *At row and column accessors, and read-only forEachReadAt / forEachReadViewAt callbacks, including cache variants, that avoid wrapping each row.

World.propagateGlobalTransformsFromTransformsReport() mirrors the MoonBit transform propagation diagnostic report, including failureReason() and the failure count getters. It does not drain upload views; call drainGlobalTransformBlobWriteViews() after inspecting the report when renderer upload should proceed.

The wrapper exposes PhaseKey, SystemContext, System, SystemRunner, and the callback-only CommandBuffer. Construct command-buffer systems with declared reads, writes, and optional structural write permission, then call SystemRunner.runPhase(world, ctx, phase). Use System.newDirect for commandless systems that mutate through World directly; these still use access guards and batching, but their direct writes are not recorded by WorldHistory.runSystemPhase. SystemRunner.planPhase(phase) uses the same cached greedy batching rule as phase execution and returns a SystemPhasePlan / SystemPlanBatch / SystemPlanSystem snapshot without executing callbacks. SystemRunner.runPhaseReport executes the same phase and returns a SystemRunReport with per-batch, per-system, and failed-command diagnostics, including direct systems and systems with empty command buffers. Use WorldHistory.runSystemPhase(..., label) or runSystemPhaseReport when command-buffer mutations must be recorded for undo/redo.

The root npm entrypoint keeps the app scheduler's string PhaseKey as PhaseKey; the ECS wrapper class is also available there as EcsPhaseKey. The rhodonite-mbt/ecs subpath exports the ECS class as PhaseKey.

Undo / Redo

Undo/redo is provided by WorldHistory, an optional tracked transaction layer over World. See Undo / Redo for scope, EntityId restoration, enabled-state behavior, and performance notes.
