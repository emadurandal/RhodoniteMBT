Glossary

This page gives short definitions for names that appear throughout RhodoniteMBT docs and code. Detailed design rules and edge cases live in the referenced pages.

TermMeaningPrimary Reference
EngineRuntime object that owns frame progression, scenes, surfaces, input, renderer, and phase handlers.Engine / Scene
SceneA unit of update and rendering. It has one World, a system runner, a main camera, and enabled/visible state.Engine / Scene
WorldECS storage for entities, components, archetypes, and builtin blob stores. It does not own GPU resources or platform loops.ECS
ECSEntity Component System: data is attached to entity IDs as components, and systems query that data to update behavior.ECS
EntityAn ID for one object in a scene. Components give it properties such as transform, renderable state, or camera state.ECS
ComponentA kind of data attached to an entity, such as Transform3D, GlobalTransform, Camera, or Renderable.ECS
SystemCode that runs in a phase, reads or writes ECS data, and may queue world mutations through a command buffer.ECS
RendererObject that extracts renderable entities from a scene and draws them with registered meshes, materials, and GPU resources.Rendering
RenderableComponent that marks an entity as drawable and points the renderer at mesh/material handles and visibility state.Rendering
SurfaceA rendering destination such as a browser canvas or native window. Each surface has local input and render target resources.Engine / Scene
PhaseA named step inside a frame, such as input, update, render extract, render, and present.Engine / Scene
BlobPacked bytes used for GPU uploads. Large builtin rows such as GlobalTransform and Camera live outside ordinary component rows.ECS
WorldHistoryOptional layer that records World mutations so editor-style actions can be undone and redone.Undo / Redo
tracked / rawTracked APIs record history; raw APIs mutate the world directly. Editors usually use tracked APIs, while runtime hot paths often use raw APIs.History Mutation Coverage
