Engine / Scene Architecture

The current runtime lives in the public facade package emadurandal/rhodonite/app. The older prototype and phase-plan text is obsolete; examples now use the facade runtime directly.

Runtime Ownership

flowchart TB E[Engine] --> GC[GPUContext] E --> T[TimeState] E --> PH[Phase handlers and groups] E --> SF[Surface list] E --> S[Scene list] SF --> SI[surface-local InputState] SF --> SS[SurfaceState] S --> W[World] S --> SR[SystemRunner] R[Renderer] --> GPU[GPU resources] R --> S W --> ECS[ECS data and builtin blobs]
TypeResponsibility
EngineOwns GPU context, scenes, surfaces, time, input, phase groups, and on-demand render state.
SceneRuntime scene with one World, one SystemRunner, a main camera, and enabled/visible flags.
WorldECS storage only; it does not own engine lifecycle or GPU resources.
RendererOwns GPU resources, mesh/material/instance tables, scene renderable extraction, and draw calls.
FrameStatePasses delta, frame index, elapsed time, surface snapshot, and optional surface input to phases and systems.

Phase Groups

flowchart TD A["rhodonite/frame_begin"] --> A1["rhodonite/surface"] A1 --> A2["rhodonite/input"] A2 --> B["rhodonite/fixed_step 0..max_fixed_steps_per_frame"] B --> B1["rhodonite/fixed_update"] B1 --> B2["rhodonite/fixed_post_update"] B2 --> C["rhodonite/render_frame"] C --> C1["rhodonite/update"] C1 --> C2["rhodonite/post_update"] C2 --> C3["rhodonite/render_extract"] C3 --> C4["rhodonite/render_prepare"] C4 --> C5["rhodonite/render"] C5 --> C6["rhodonite/present"]

Engine::run_frame(delta_seconds) runs frame-begin, fixed-step, and render-frame groups in the standard order. Each phase runs before-system handlers, scene systems, and after-system handlers.

  • phase_startup() and phase_shutdown() are one-shot phases, not group members.
  • Custom phase group/order edits are performed during Engine::initialize() startup handlers.
  • Engine::add_phase_handler can take a registration key; handlers with the same phase, slot, and key are deduplicated.
  • MoonBit samples declare standard transform/camera runtime integration with Scene::use_common_runtime; the scene uses the builtin orbit/home/lens component ids and boolean flags choose optional standard systems such as orbit camera blob sync. TypeScript samples use the matching Scene.useCommonRuntime. Engine::initialize() reflects that declaration into common scene systems and orbit-camera input handlers. In TypeScript, the default transform propagation calls world.updateGlobalTransformsFromTransforms() when the scene world exposes it; custom worlds can pass propagateTransforms, and samples can disable propagation with transformPropagation: false. Binding a scene with Engine::set_surface_scene / Engine.setSurfaceScene also installs any declared orbit-camera input handler for that scene.
  • Scene-only or offscreen rendering code can call Scene::prepare_render_state to run update, post_update, and render_extract once without spelling out each phase.
  • When a surface is suspended, update phases still run and render extraction/prepare/render/present are skipped.
  • In on-demand mode, no frame runs while the engine is clean; visible state changes must call request_render.

Surface Model

Single-surface code updates the current snapshot through set_surface_active and set_surface_suspended. Multi-surface code uses add_surface, add_surface_for_scene, set_surface_scene, surface_input, and run_multi_surface_frame. Every surface has surface-local input.

Renderer v1

Renderer is currently an intentionally narrow engine-owned renderer. It queries visible Renderable + GlobalTransform entities, uploads the scene main camera's builtin Camera blob and GlobalTransform blob, and draws unlit static indexed meshes.

  • handles: MeshHandle, MaterialHandle, InstanceBufferHandle
  • components: RenderableDesc, RenderableFlags, scene-owned Scene::renderable_component; register_renderable_component remains available for raw worlds
  • primitive descriptors: StaticIndexedMeshDesc, CubeMeshDesc, cube_mesh_desc
  • resources: register_static_indexed_mesh_desc, register_cube_mesh, register_unlit_material, register_static_instance_buffer
  • draw paths: render_scene_renderables and render_instanced_mesh for MassCubes

Textures, skinning, transparent sorting, shadows, and LOD are not v1 renderer responsibilities yet.
