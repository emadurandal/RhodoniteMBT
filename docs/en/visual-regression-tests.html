Visual Regression Tests

Visual regression tests render real sample paths through WebGPU, read back RGBA8 pixels, and compare them with PNG golden files. Browser and native samples both run through their Platform single-frame paths so Engine setup, common runtime handlers, surface configuration, and presentation are covered.

Flow

flowchart LR M[visual_samples.tsv] --> H[Native or browser harness] H --> E[Sample setup_engine] E --> R[Platform single-frame render] R --> B[RGBA8 readback] B --> P[PNG compare or update] P --> G[__image_snapshots__]

Commands

pnpm run test:examples:visual
pnpm run test:examples:visual:native
pnpm run test:examples:visual:browser
pnpm run test:examples:visual:update
pnpm run test:examples:visual -- --verbose

Manifest And Snapshots

The matrix lives in visual_samples.tsv. Each row contains target, id, display name, PNG filename, max_mismatch_rate, and perceptual_threshold. Golden PNGs live in __image_snapshots__.

Comparison

  • Native tests capture the SDL3 Platform single-frame presentation, decode PNGs with mizchi/image, and compare with mizchi/pixelmatch.
  • Browser tests decode/encode PNGs in Chrome/Chromium using createImageBitmap and OffscreenCanvas, then POST results to the Node runner.
  • The current manifest generally uses max_mismatch_rate=0.0005 and a perceptual threshold around 0.1.
  • Snapshot updates write current WebGPU readback output back to PNGs. Inspect the rendered change before updating.

Implementation Notes

  • Native overrides webgpu_objects/native and captures the next canvas presentation before presenting; browser overrides webgpu_objects/js.
  • scripts/run-visual-regression.mjs routes native/browser runs and hides MoonBit warnings unless verbose mode is enabled.
  • scripts/run-browser-visual-regression.mjs starts Vite, a result server, and a headless Chrome/Chromium page.
  • On machines without WebGPU adapter support or Chrome/Chromium, tests print a skip message and pass without comparing pixels.
