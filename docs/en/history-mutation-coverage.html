History Mutation Coverage

This page is the audit table for ECS mutation APIs and their Undo/Redo behavior. When adding a mutating API, update this page and add or extend the matching coverage test.

The TypeScript wrapper follows the same classification as the MoonBit surface. Public wrapper methods should either delegate to the tracked API listed here, remain raw guarded, or be documented as intentionally untracked with matching TypeScript coverage when the wrapper adds behavior.

The TypeScript public wrapper surface is also checked by history-mutation-coverage.test.ts. If a method is added to World, WorldHistory, query rows, raw query archetypes, SystemRunner, or CommandBuffer, classify it in that audit as tracked, tracked callback, tracked command phase, raw guarded, intentionally untracked, read-only, or history-control.

The same test audits the MoonBit public surface from pkg.generated.mbti. After adding or removing a public ECS method and refreshing interfaces with moon info, update the MoonBit ledger in that test so the method has an explicit history classification.

Tracked API parity is also audited across the MoonBit public surface, js_bridge, ecs-bridge.d.ts, and the TypeScript wrapper. When adding a tracked Undo/Redo API, update the bridge declaration, wrapper import, public wrapper method or mirror export, and parity ledger in the same change. MoonBit-only typed helpers must stay explicitly listed as MoonBit-only until they receive a TypeScript bridge.

Coverage Classes

ClassBehaviorExpected tests
TrackedThe API records reversible deltas through WorldHistory.Undo and redo restore the before and after state.
Tracked callbackThe API lends mutable bytes in a callback and records changes at the callback boundary.Guarded transactions allow the tracked callback and raw callbacks abort.
Tracked command phaseThe system queues commands and WorldHistory::run_system_phase applies them through tracked APIs.Queued commands become one undoable record under the phase label.
Raw guardedThe API intentionally bypasses history, but guarded transactions abort it.A guarded transaction has a panic/throw coverage test.
Intentionally untrackedThe API updates derived runtime data, registration metadata, or readback plumbing.Docs explain why it is outside history scope.
History-controlThe API changes history state or scopes tracked operations without directly mutating component data.Control-flow tests cover commit, cancel, disabled, and nested cases.
