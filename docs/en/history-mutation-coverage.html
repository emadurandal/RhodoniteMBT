History Mutation Coverage

This page is the audit table for ECS mutation APIs and their Undo/Redo behavior. When adding a mutating API, update this page and add or extend the matching coverage test.

Coverage Classes

ClassBehaviorExpected tests
TrackedThe API records reversible deltas through WorldHistory.Undo and redo restore the before and after state.
Tracked callbackThe API lends mutable bytes in a callback and records changes at the callback boundary.Guarded transactions allow the tracked callback and raw callbacks abort.
Tracked command phaseThe system queues commands and WorldHistory::run_system_phase applies them through tracked APIs.Queued commands become one undoable record under the phase label.
Raw guardedThe API intentionally bypasses history, but guarded transactions abort it.A guarded transaction has a panic/throw coverage test.
Intentionally untrackedThe API updates derived runtime data, registration metadata, or readback plumbing.Docs explain why it is outside history scope.

Tracked Surface

SurfaceCoverage expectation
WorldHistory::create_entity, create_entities, destroy_entityEntity ids and generations survive undo/redo, including destroy restore.
add_component, add_component_bytes, set_component_bytes, remove_componentComponent presence and payload bytes round-trip.
add_component_bytes_many, set_component_bytes_manyBulk helpers validate first, record one operation, and restore every affected row.
spawn_batchSpawned entities and initialized component rows undo and redo as a batch.
set_transform_trs, set_child_ofAuthoring transform and parent relationship rows are restored.
set_global_transform, set_global_transform_format, set_camera_matricesBlob-backed builtin presence and logical row payloads are restored through dedicated helpers.
Tracked camera-control helpersOrbit setup, lens, controller, home, transform sync, and blob sync helpers group editor steps into undoable records.

Query And Command Surface

SurfaceUndo/Redo status
QueryRow::write_tracked, RawQueryRow::write_trackedTracked callback APIs for row authoring. They delegate without history copies when recording is disabled.
RawQueryArchetype::write_column_trackedTracked callback API for full-column edits. It snapshots the column and records changed rows.
RawQueryArchetype::write_column_rows_trackedTracked callback API for sparse column edits when the caller already knows the candidate rows. It snapshots and records only those row views.
CommandBuffer through WorldHistory::run_system_phaseTracked command path for editor systems. Supported queued commands dispatch through the corresponding history methods.
Raw QueryRow::write, RawQueryRow::write_view, RawQueryArchetype::write_columnRaw guarded. These are untracked and abort inside guarded history transactions.
Raw SystemRunner::run_phaseRaw guarded. Use WorldHistory::run_system_phase for command-buffer edits that need history.

Raw And Untracked Surface

SurfaceStatus
Direct World mutators and raw World::spawn_batchRaw guarded. Runtime systems and simulation may use them outside guarded editor transactions.
Component registration and identity metadataIntentionally untracked. Component schemas are part of application setup, not per-operation editor history.
GlobalTransform / Camera blob upload, drain, resize, dense write, and readback helpersIntentionally untracked derived data. Use dedicated WorldHistory helpers for authoring changes.
Transform propagation and camera view update systemsIntentionally untracked derived recomputation.
Read-only queries and component metadata readsNo history behavior required.
