Module Boundaries

RhodoniteMBT is a MoonBit workspace joined by the root moon.work. Library modules keep clear ownership boundaries; examples are repository-only and are not published as release units.

How To Read This Page

Use this page first to learn which directory owns which part of the project. If you are only using the runtime, start with the emadurandal/rhodonite facade and the samples. Lower modules exist so CPU-only logic, WebGPU wrappers, and native SDL3 runtime code can be maintained separately.

Workspace Modules

ModuleDirectoryRole
emadurandal/sdl3moon/sdl3SDL3 MoonBit binding fork used by native runtime packages.
emadurandal/rhodonite_coremoon/rhodonite_coreMath, binary writes, JS bridge, CPU-only ECS, platform-independent input, and ECS benchmarks.
emadurandal/rhodonite_webgpumoon/rhodonite_webgpuWebGPU abstraction with browser and native object backends selected through a virtual package.
emadurandal/rhodonitemoon/rhodonitePublic facade: Engine, Scene, Renderer, browser platform helpers, and TypeScript app wrapper.
emadurandal/rhodonite_app_sdl3moon/rhodonite_app_sdl3SDL3 native app runtime helpers for windows, events, resize, suspended surfaces, and WebGPU bootstrap.
emadurandal/rhodonite_examplesmoon/rhodonite_examplesRunnable samples, visual regression harnesses, and sample-only shared helpers.

Dependency Direction

flowchart LR sdl3["sdl3"] core["rhodonite_core"] webgpu["rhodonite_webgpu"] facade["rhodonite facade"] app_sdl3["rhodonite_app_sdl3"] examples["rhodonite_examples"] webgpu --> core facade --> core facade --> webgpu app_sdl3 --> facade app_sdl3 --> core app_sdl3 --> webgpu app_sdl3 --> sdl3 examples --> facade examples --> app_sdl3 examples --> core examples --> webgpu
  • rhodonite_core does not know GPU devices, DOM, SDL3, or platform loops.
  • rhodonite_webgpu/webgpu_objects is virtual. The default stub keeps workspace-wide checks buildable; runnable packages override it with js or native.
  • The runtime facade lives in emadurandal/rhodonite/app. Browser platform code lives in emadurandal/rhodonite/app/browser; SDL3 platform code lives in emadurandal/rhodonite_app_sdl3/sdl3.
  • Examples may import both the facade and lower modules, but library modules must not depend on examples.

Release Units

Maintainer / Agent Notes

The remaining sections are maintainer-oriented release, npm package, and validation notes. When module dependencies or package entrypoints change, keep this table, README, and related scripts in sync in the same change.

Mooncakes publishing runs in dependency order. The root script temporarily rewrites workspace path dependencies to registry versions, publishes, then restores the workspace files.

  1. emadurandal/sdl3
  2. emadurandal/rhodonite_core
  3. emadurandal/rhodonite_webgpu
  4. emadurandal/rhodonite
  5. emadurandal/rhodonite_app_sdl3
pnpm run publish:moon
PUBLISH_MOON_DOWNSTREAM_ONLY=1 pnpm run publish:moon
PUBLISH_MOON_APP_SDL3_ONLY=1 pnpm run publish:moon

emadurandal/rhodonite_examples is repository-only and is not published by the script.

npm Package

packages/rhodonite-mbt is an ESM-only npm package. It exports root, ./math, ./ecs, and ./app. It bundles TypeScript wrappers plus the MoonBit JS bridge, not examples or SDL3 native runtime code.

pnpm run build:npm
pnpm run pack:npm
pnpm run publish:npm
